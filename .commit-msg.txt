fix(server,store): apply the 04608be review findings

R1: the host scenario-item path reused ChangeItem(ActivateItem), which returns
early whenever the row's inUse flag is already set. That is the idempotence
SwitchInUse needs, but not what UseItem does. Store.UseInGameItem now mirrors the
default branch of CItemManager::UseItem: CanUseItem still refuses an exhausted or
selected row, a row carrying a relative duration is spent extending another
active copy of the same item (ExtendItem with duration=false, then RemoveItem),
and otherwise the row becomes selected with its duration converted to an absolute
timestamp. Other copies are not deselected, as in the reference.

N1: tracking the archive made every ./... pattern walk the overlay sources, so
build, vet and test failed at the root. A go.mod inside code-review/probes draws a
module boundary there; the archive layout, the overlay absolute paths and the
documented commands stay as they were.

N2: room settings were corrected and stored, then the raw request was broadcast,
so the room saw values the server had rejected. settings.writeMasked encodes the
request's mask with the effective field bytes, matching
CChannelManager::OnRoomUpdateSettings, which sends newSettings' flags with the
room's current values. A field the room cleared keeps the request's width and
carries zeros so the frame stays well formed.

N3: a migrated host kept the previous host's item-backed settings, so superRoom
could still allow super-host kicks. leaveRoom now re-runs CheckForHostItems for the
new host and broadcasts superRoom, c4Timer and (for the modes that use it) sd one
field at a time, in the reference's order.

The social fixture gained a real store because leaving a room now reads the new
host's inventory.
