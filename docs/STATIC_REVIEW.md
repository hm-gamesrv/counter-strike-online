## 修复的问题

| 问题与触发条件 | 修复 |
| --- | --- |
| 未发送版本包即可用聊天命令注册、登录，绕过版本检查 | 聊天命令必须在成功的版本握手后处理；已登录会话拒绝重新开始登录握手 |
| 关闭期间刚接收的连接可能漏过连接清理 | 将取消检查与连接登记放在同一把锁内，关闭刚接收的连接 |
| 背包按固定 400 条拆包，皮肤列表使实际帧超长 | 按序列化后的字节数分包，统一全量和增量路径；单条超长或槽位越界时不返回部分包 |
| 新物品忽略 `nextInventorySlot`，并以固定 65500 判断槽位上限 | 同时遵守持久化的下一个槽位和默认物品偏移，避免重用已删除槽位及 uint16 回绕 |
| 玩家设置请求可保存，但回传时多出的尾字段使帧超长 | 保存前校验回传包所需空间；读取已有设置时也检查长度 |
| 主机存档接近帧上限，迁移时添加参与者列表后溢出 | 接收存档时预留迁移头和最多 32 名参与者编号的空间 |
| 商店子商品条数、价格、数量、时长或广告类型超出协议字段，或重复 JSON 键造成编号歧义 | 加载时校验字段范围、重复键和全部商店包的编码长度 |
| 基础奖励先相乘再封顶，大系数可能先溢出 | 先判断是否达到上限再相乘；经验累计同样先计算剩余空间 |
| 积分、累计击杀和死亡相加溢出，SQLite 可能改存浮点数或客户端字段截断 | 在事务内附带累加边界条件，失败时回滚发奖和结算去重记录 |
| 结果页的经验角色加成字段误用了积分加成；单局死亡数可超过 uint16 | 分别写入经验和积分加成，限制死亡计数范围 |
| 空请求被按默认子类型处理，非法配置到运行时才暴露 | 提前检查子类型读取错误；补充端口、房主模式、初始背包、槽位和加成比例检查 |

修改了与删除行为相关的测试，并补充了变长背包、槽位偏移、奖励溢出和版本握手的回归用例。本轮只编译这些用例，不运行。
